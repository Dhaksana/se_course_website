Data Design

Description: Translating information models to DB schemas and data structures.

Typical Artifacts: ER Diagrams, Schema definitions, Data Dictionaries.

Common Mistake: Ignoring data normalization or relying purely on arrays instead of DBs for large data.

Exam Phrasing: "How do you map the conceptual ERD to a physical database?"

Architectural Design

Description: The overall structure of the software, identifying major subsystems.

Typical Artifacts: Component Diagrams, Layered logic models.

Common Mistake: Choosing an architecture based on "hype" rather than evaluating quality attributes (e.g., using microservices for a tiny app).

Exam Phrasing: "Justify an architectural style for a distributed banking system."

Interface Design

Description: Defining how the system interacts with users and other systems.

Typical Artifacts: Wireframes, API Specs (Swagger/OpenAPI).

Common Mistake: Forgetting error states on API endpoints or poor consistency in GUI design.

Exam Phrasing: "Explain the principle of consistency in UI design."

Component Design

Description: The algorithms and class internals that make the system work.

Typical Artifacts: Class Diagrams, Activity Diagrams, Pseudocode.

Common Mistake: Creating "God Classes" (low cohesion) or heavily coupled modules.

Exam Phrasing: "Differentiate between cohesion and coupling."

Deployment Design

Description: Mapping software to physical hardware nodes.

Typical Artifacts: UML Deployment Diagram, Network Topology maps.

Common Mistake: Assuming instantaneous network calls (ignoring latency realistically).

Exam Phrasing: "Draw a deployment diagram mapping a 3-tier web app to cloud servers."
