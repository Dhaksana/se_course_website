Mastering Scrum in OpenProject

OpenProject is a powerful tool for Agile teams, but it treats data differently than Jira or Trello. This guide provides detailed instructions on how to author, structure, and execute a Scrum project.

Golden Rule

In OpenProject, Epics, Stories, Bugs, and Tasks are all Work Packages. You differentiate them by changing their Type. The "Scrum" view is simply a specific way of filtering and visualizing these Work Packages.

Start Here (10-Minute Setup)

This is a one-page checklist you can follow in order, even if you have never used OpenProject before (beyond having an account).

  1. Open your project and confirm you can access Project settings in the left sidebar.
  2. Go to Project settings → Modules.
  3. Enable Backlogs and Taskboard, then click Save.
  4. Go to Work packages and confirm you can see the green + Create button.
  5. Create one Epic as your container for work.
  6. Create two User Stories and set their Parent to the Epic.
  7. Go to Backlogs and create one Sprint (a Version) named "Sprint 1" with dates.
  8. Drag both User Stories from the Product Backlog into "Sprint 1".
  9. Open Taskboard, select "Sprint 1" from the dropdown, and confirm your stories appear.
  10. Move one item across the workflow columns to confirm you can update progress during the sprint.

Roles Mapping

Scrum Role What they do in OpenProject Where in the UI
Product Owner Owns and prioritizes the Product Backlog. Writes Epics and User Stories, clarifies acceptance criteria, and decides what is ready for sprint planning. Work packages to create Epics/Stories; Backlogs to prioritize and assign stories to sprints.
Scrum Master Ensures the workflow is usable, supports sprint ceremonies, helps remove blockers, and ensures the team can operate smoothly in the tool. Project settings → Modules for setup; Backlogs and Taskboard for sprint execution.
Developers Break stories into tasks, update status during the sprint, log remaining work if used, and close work packages when done. Taskboard for daily work; open individual work packages for details, assignments, and status updates.
Stakeholders Review progress and outcomes, provide feedback, and follow changes without needing to manage the backlog day-to-day. Work packages (filtered views), and sprint results in Backlogs depending on access.

Mini Example: Epic → Sprint → Done

This is a fully worked, minimal path you can replicate in a fresh project. The goal is not completeness; it is to get one coherent loop working end-to-end.

Step A: Create one Epic

  1. Go to Work Packages.
  2. Click + Create and select Epic.
  3. Set Subject to “User Authentication”.
  4. Write a short Description explaining the goal: users can sign up and log in securely.
  5. Save.

Step B: Create two User Stories under that Epic

  1. Click + Create and select User Story.
  2. Subject: “As a visitor, I want to create an account, so that I can access protected features.”
  3. Set Story Points to 3 and set Parent to “User Authentication”. Save.
  4. Create a second story: “As a user, I want to log in, so that I can access my account.”
  5. Set Story Points to 2 and set Parent to “User Authentication”. Save.

Step C: Create one Sprint and pull the stories into it

  1. Go to Backlogs.
  2. Create a new Sprint (Version) named “Sprint 1” and set start/end dates.
  3. Drag both User Stories from the Product Backlog column into “Sprint 1”.

Step D: Move work to Done during the sprint

  1. Go to Taskboard.
  2. Select “Sprint 1” in the Sprint dropdown.
  3. During execution, team members move cards across columns as status changes.
  4. When a story is completed and accepted, move it to the final status used by your workflow (often “Closed”).
What you should observe:

The Epic becomes your top-level container, the Sprint (Version) becomes the timebox, and the Taskboard becomes the day-to-day execution view. If the stories are correctly linked to the Epic using the Parent field, you preserve hierarchy and reporting across the project.

Scrum Configuration

Before writing a single story, you must ensure your project is "Agile-aware". By default, OpenProject may hide the Backlogs module.

Enable the Backlogs Module

  1. Go to your project's homepage.
  2. Click Project Settings (sidebar) → Modules.
  3. Ensure the checkbox for Backlogs is selected.
  4. Ensure the checkbox for Taskboard is selected.
  5. Click Save.

2. Defining Epics (The "Big Picture")

Epics serve as the container for your work. They represent large initiatives that cannot be completed in a single sprint.

How to Create an Epic

You do not create Epics in the Backlog view; you create them in the standard Work Package list.

  1. Click Work Packages in the sidebar.
  2. Click the green + Create button in the top-right.
  3. Select Epic from the dropdown list.
  4. Subject: Enter a broad title (e.g., "New Checkout Experience").
  5. Description: Describe the strategic value.
  6. Status: Set to "New" or "In Specification".

Figure 1: The Global Create Button allows you to select "Epic" or "User Story".

3. User Stories & The Hierarchy

This is the most critical step. If you do not link Stories to Epics, you will lose the ability to see progress bars and roadmaps.

Creating a Story

  1. Click + Create → User Story.
  2. Subject: Use the standard format: "As a [role], I want [feature], so that [benefit]."
  3. Select Epic from the dropdown list.
  4. Subject: Enter a broad title (e.g., "New Checkout Experience").
  5. Story Points: Enter your estimate (Fibonacci: 1, 2, 3, 5, 8...).

Linking to the Parent (The Hierarchy)

While creating (or editing) the User Story, you must create the Parent-Child relationship.

  1. In the User Story form, locate the Parent field.
  2. Type the name of the Epic you created in Step 2.
  3. Select Epic from the dropdown list.
  4. Select the Epic from the autocomplete list.
  5. Save the story.

Tip

In the Work Packages list view, your stories will now appear indented under the Epic. This visual hierarchy confirms the link is active.

Figure 2: The Hierarchy View. Note how child items are indented under the Parent Epic.

4. Backlog Management (Sprint Planning)

Now that you have authored stories, it is time to plan a Sprint. In OpenProject, Sprints are managed in the Backlogs view.

Understanding the View

  • Left Column (Product Backlog): This lists all open User Stories that are not yet assigned to a sprint.
  • Right Column (Versions/Sprints): This lists your sprints. In OpenProject, a Sprint is technically a "Version".

Step-by-Step Planning

  1. Click Backlogs in the sidebar.
  2. Create a new Sprint by clicking the arrow next to "Versions" on the right -> + New Version.
  3. Name it (e.g., "Sprint 1") and set the dates.
  4. Drag and Drop: Click a User Story in the left column and drag it into the Sprint column on the right.
  5. Observe the total Story Points calculating automatically at the top of the Sprint column to ensure you don't overcommit.

Figure 3: Moving items from the Product Backlog to a Sprint backlog in the Backlogs view.

5. Execution: The Taskboard

Once the Sprint begins, the team leaves the "Backlogs" view and moves to the "Taskboard" for their daily standups.

How to use the Taskboard

You do not create Epics in the Backlog view; you create them in the standard Work Package list.

  1. Click Taskboard in the sidebar.
  2. Ensure the current Sprint is selected in the top-right dropdown.
  3. You will see columns matching your workflow (e.g., New, In Progress, Closed).
  4. Action: Team members drag cards from left to right as they complete work.
  5. Burndown: Clicking the "Burndown" chart icon at the top right will show the team's velocity against the remaining days.
