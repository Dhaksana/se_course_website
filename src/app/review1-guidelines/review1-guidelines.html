SE Sprint Review 1

Guidelines for Sprint Review 1

OpenProject

  • The OpenProject project must contain all the Epics, User Stories and Tasks
  • Tasks must have appropriate priority and Story Points estimated
  • A backlog must be created for Sprint 1 with the corresponding tasks
  • Similarly, a board must be created with columns TODO, In Progress and Done, containing all the Sprint 1 tasks.
  • All meetings must be updated on OpenProject
  • Minutes of the meeting must be maintained as a notebook.

GitHub & Codebase

  • It is preferable to have a loosely coupled backend and frontend, in separate repositories. Monorepos must have appropriate justification, as separate repositories simplifies developments and ensures a cleaner commit history.
  • Ensure that all team members commit code regularly to GitHub.
  • The codebase must have comments where appropriate. Developer documentation must be present in the README file. API Documentation is also necessary.

Diagrams

The following diagrams are compulsory for all teams:

  1. Use Case Diagram
  2. Sequence Diagram
  3. Architecture Diagram
  4. Schema diagram (or alternatively ER Diagram)

Additional diagrams may be included if appropriate for the domain chosen.

DevOps Strategy

The DevOps strategy must include a diagram and a document. The strategy must identify the following for each of the components in the project:

  • corresponding source code repos
  • the location where the component is deployed
  • the tests or checks to be performed before deployment

Any tools, platforms and libraries to be used for this must be specified.

Testing Strategy

The testing strategy must specify how each component of the project will be tested. This includes the kinds of tests to be written, as well as the properties for which each component will be tested. All tools, platforms, libraries and frameworks that will be used for testing must be specified.
